## Important Implementation Notes & Fixes
- Vitest was initially picking up Playwright E2E test files. Fixed by restricting Vitest to unit files in vitest.config.ts:
  - include: ['tests/unit/**/*.test.{ts,tsx}']

- Unit tests had some ambiguous assertions (numbers matching multiple textual occurrences like 5 or 2,500), so I made them use exact matches or proper formatting:
  - Use exact match or the formatted string: `getByText(/^5$/)` or `getByText(/2,500/)`.

- Playwright E2E ran into duplicate matches for headings like "Fitness Progress Tracker", and the test saw multiple matches for "Goals" due to smaller descriptive strings. Resolved by using role-based selectors:
  - `page.getByRole('heading', { name: /Fitness Progress Tracker/i })`
  - `page.getByRole('heading', { name: /Activity Overview/i })`
  - `page.getByRole('heading', { name: /Goals/i })`

- Playwright initial episodes found the dev server port in use, leading it to pick a fallback port (5174). I changed Playwright's `baseURL` / `webServer.port` to match the running dev server’s port to avoid instances of "port already used".
